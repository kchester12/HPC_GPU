The starting playbook

This playbook targets every host in the compute group. It installs Prometheus node_exporter, pushes a shared slurm.conf, and makes sure slurmd is running. If slurm.conf changes, a handler restarts slurmd.

# site.yml
- hosts: compute
  become: true
  vars:
    slurm_conf_src: files/slurm.conf
  tasks:
    - name: Install node_exporter
      ansible.builtin.dnf:
        name: golang-github-prometheus-node-exporter
        state: present

    - name: Push slurm.conf
      ansible.builtin.copy:
        src: "{{ slurm_conf_src }}"
        dest: /etc/slurm/slurm.conf
        mode: "0644"
      notify: restart slurmd

    - name: Ensure slurmd running
      ansible.builtin.service:
        name: slurmd
        state: started
        enabled: true

  handlers:
    - name: restart slurmd
      ansible.builtin.service:
        name: slurmd
        state: restarted

How the pieces fit

Piece What it does
hosts: compute Runs against the compute group in your inventory
become: true Uses sudo for every task
vars Values you can reuse; {{ slurm_conf_src }} is replaced at run time
tasks Run in order on every host; each one describes a desired state, not a command
notify / handlers A handler runs once at the end of the play, only on hosts where a notifying task reported a change

Because each task describes a state, running the playbook twice is safe. The second run should report ok everywhere and changed=0.

A minimal inventory

# inventory.ini
[compute]
node[001:064]

[controller]
slurmctl01

Running it safely

ansible-playbook -i inventory.ini site.yml --check --diff     # dry run: show what would change
ansible-playbook -i inventory.ini site.yml --limit node001     # try one node first
ansible-playbook -i inventory.ini site.yml                     # then everyone

Improvements before using it on a live cluster

  • Start node_exporter too. The playbook installs it but never enables it. Add a service task for node_exporter with state: started and enabled: true. On Rocky 9 the package comes from EPEL, and names can differ between repos, so confirm with dnf search node-exporter.

  • Don't restart every slurmd at once. A handler fires on every host where slurm.conf changed, which can be all of them simultaneously. Add serial: "20%" to the play to roll through nodes in batches. For most config changes, a single scontrol reconfigure on the controller is enough, and you can run that once instead:

    handlers:
  - name: reconfigure slurm
    ansible.builtin.command: scontrol reconfigure
    delegate_to: slurmctl01
    run_once: true

  • Push slurm.conf to the controller as well. Slurm expects the same slurm.conf everywhere. Include the controller group, or use configless Slurm so nodes fetch it from slurmctld.

  • Set ownership explicitly. Add owner: root and group: root to the copy task so a stray local file permission doesn't propagate.
  • Keep the playbook and files/slurm.conf in git. Every change to the cluster config then has a history and a rollback.
Examples are generic. Verify commands and defaults against your vendor and scheduler documentation before production use.
