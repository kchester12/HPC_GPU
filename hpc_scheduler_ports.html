Default communication ports for Slurm, IBM LSF, Grid Engine and PBS, plus the identity, storage, monitoring and management services a cluster depends on.

Defaults, not guarantees. Every port below can be changed in configuration. On an existing cluster, check the running config (see Verify) before writing firewall rules.

Firewall pitfalls

  • Callbacks to the submit host. The most common breakage is blocking traffic going back to login nodes: Slurm srun I/O and step callbacks, LSF RES for interactive jobs, and Grid Engine qrsh. Pin those ranges and open them on login nodes.
  • LSF UDP. Opening only TCP 7869 leaves LIM heartbeats dropped, and hosts flap to unavail.
  • Bidirectional daemons. Controllers push to node daemons (slurmd, sbatchd, sge_execd) as well as receive from them.
  • Time drift. A blocked NTP port shows up later as MUNGE credential failures or Kerberos errors, not as an obvious network problem.
  • Common pattern. Treat the compute and fabric network as trusted and firewall only the login nodes, the controller and the management network.

Verify on your cluster

# Slurm
scontrol show config | grep -Ei 'port|SrunPortRange'

# LSF
grep -E 'PORT' $LSF_ENVDIR/lsf.conf

# Grid Engine
grep PORT $SGE_ROOT/$SGE_CELL/common/settings.sh   # or check /etc/services

# What is actually listening
ss -tulpn | grep -E 'slurm|lim|res|batchd|sge|pbs'
Examples are generic. Verify ports and defaults against your vendor and scheduler documentation before production use.
