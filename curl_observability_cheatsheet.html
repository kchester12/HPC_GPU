The pattern every tool follows

What Where to look
Is it alive? /-/healthy, /ready, /api/health, /healthz
What does it measure about itself? /metrics
How do I query or manage it? /api/v1/... or /api/v2/... (JSON, pipe to jq)

Six curl habits

curl -sS  URL | jq .                                   # quiet, but show errors; pretty JSON
curl -fsS URL                                          # fail (non-zero exit) on HTTP >= 400: for scripts
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' URL   # status + timing only
curl -v   URL                                          # can't connect? see DNS/TCP/TLS/headers
curl -sG  URL --data-urlencode 'query=...'             # ALWAYS for PromQL / LogQL
curl -sS  -H @~/.token.hdr URL                         # auth header from a file, not the command line

Prometheus (P=http://localhost:9090)

curl -fsS $P/-/ready                                                     # ready to serve queries?
curl -s $P/api/v1/status/runtimeinfo | jq .data.reloadConfigSuccess      # did my last config edit apply?
curl -s -X POST $P/-/reload                                              # reload (needs --web.enable-lifecycle)

# which targets are down, and why
curl -s $P/api/v1/targets | jq -r '.data.activeTargets[] | select(.health!="up") | "\(.scrapeUrl)  \(.lastError)"'

# run any PromQL
curl -sG $P/api/v1/query --data-urlencode 'query=up == 0' | jq -r '.data.result[].metric.instance'

# firing alerts, as Prometheus sees them
curl -s $P/api/v1/alerts | jq -r '.data.alerts[] | "\(.state)\t\(.labels.alertname)\t\(.labels.instance)"'

# top 10 metrics by series count (memory / cardinality problems)
curl -s $P/api/v1/status/tsdb | jq -r '.data.seriesCountByMetricName[] | "\(.value)\t\(.name)"'

Exporter /metrics

curl -s http://node01:9100/metrics | grep '^node_load'                      # read raw values
curl -s http://node01:9100/metrics | grep -vc '^#'                          # how many series
curl -s -o /dev/null -w '%{time_total}s\n' http://node01:9100/metrics       # scrape time vs scrape_timeout

Alertmanager (AM=http://localhost:9093)

curl -s $AM/api/v2/alerts | jq -r '.[] | "\(.status.state)\t\(.labels.alertname)\t\(.labels.instance)"'
curl -s $AM/api/v2/silences | jq -r '.[] | select(.status.state=="active") | "\(.id)\t\(.endsAt)\t\(.comment)"'

# 2-hour maintenance silence for one node
curl -s -X POST $AM/api/v2/silences -H 'Content-Type: application/json' -d "{
  \"matchers\":[{\"name\":\"instance\",\"value\":\"node01.*\",\"isRegex\":true,\"isEqual\":true}],
  \"startsAt\":\"$(date -u +%FT%TZ)\",\"endsAt\":\"$(date -u -d '+2 hours' +%FT%TZ)\",
  \"createdBy\":\"$USER\",\"comment\":\"maintenance\"}" | jq -r .silenceID

curl -s -X DELETE $AM/api/v2/silence/<silenceID>                          # expire it

Grafana (G=http://localhost:3000, token in ~/.grafana_token)

AUTH="Authorization: Bearer $(cat ~/.grafana_token)"
curl -s $G/api/health                                                     # no auth needed
curl -s -H "$AUTH" $G/api/datasources | jq -r '.[] | "\(.uid)\t\(.name)\t\(.url)"'
curl -s -H "$AUTH" "$G/api/search?type=dash-db&query=node" | jq -r '.[] | "\(.uid)\t\(.title)"'
curl -s -H "$AUTH" $G/api/dashboards/uid/<uid> | jq .dashboard > dash.json   # export / back up

# annotation on every graph (maintenance, upgrades, reboots)
curl -s -H "$AUTH" -H 'Content-Type: application/json' $G/api/annotations \
  -d "{\"time\":$(date +%s%3N),\"tags\":[\"maintenance\"],\"text\":\"slurmctld upgraded\"}"

Loki (L=http://localhost:3100)

curl -fsS $L/ready
curl -s $L/loki/api/v1/labels | jq -r '.data[]'
curl -sG $L/loki/api/v1/query_range --data-urlencode 'query={job="varlogs"} |= "error"' \
  --data-urlencode 'limit=20' | jq -r '.data.result[].values[][1]'

OpenTelemetry Collector

curl -fsS http://localhost:13133/                                         # health_check extension
curl -s http://localhost:8888/metrics | grep -E 'otelcol_(receiver_accepted|exporter_send_failed)'

When something is wrong

Symptom First command
Connection refused curl -v URL, then ss -ltnp | grep PORT on the host
Hangs / times out curl -v --connect-timeout 3 URL, then check firewalld
Target up == 0 curl the scrape URL from the Prometheus host
bad_data: parse error You forgot -G --data-urlencode
Config change ignored runtimeinfo → reloadConfigSuccess; promtool check config
Alert fired, no notification $P/api/v1/alertmanagers → $AM/api/v2/alerts → $AM/api/v2/silences
Grafana "No data" Run the same query against the backend directly

Shortcuts

Load scripts/obs-functions.sh in your ~/.bashrc to get promq, promdown, promalerts, amalerts, amsilence, lokiq, scrapetime and httpcheck. Run scripts/obs-check.sh <host> for a one-shot health check of the whole stack.

Examples are generic. Verify commands and defaults against your vendor and scheduler documentation before production use.
