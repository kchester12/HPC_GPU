Slurm GPU Partition Hardening Checklist

A security hardening checklist for GPU nodes under Slurm on Rocky Linux 9: isolation, access, drivers, containers, monitoring, fabric, and firmware.

How to use this: test each change on one node before rolling it out, and confirm option names against your Slurm and driver versions.

1. Device isolation (Slurm and cgroups)

  • slurm.conf: use cgroup-based tracking and task plugins.

    ProctrackType=proctrack/cgroup
TaskPlugin=task/cgroup,task/affinity
GresTypes=gpu
PrologFlags=Contain

  • cgroup.conf: constrain devices, cores, and memory so jobs only see their allocated GPUs. Rocky 9 uses cgroup v2 by default.

    CgroupPlugin=cgroup/v2
ConstrainDevices=yes
ConstrainCores=yes
ConstrainRAMSpace=yes

  • gres.conf: use AutoDetect=nvml so Slurm maps GPUs, including MIG slices, from the hardware. Hand-written device paths can drift.

  • Verify: run a 1-GPU job on a multi-GPU node and confirm nvidia-smi inside it shows only one device.

2. Node access control

  • pam_slurm_adopt: add it to the account section of /etc/pam.d/sshd so users can only SSH to nodes where they have a running job. The session is adopted into the job's cgroup, so it inherits the GPU restriction. Requires PrologFlags=Contain.
  • Remove pam_systemd from the sshd stack. Otherwise systemd moves the SSH session into its own user slice and it escapes the job's cgroup.
  • Admin exemption: exempt admins with a pam_access rule placed before pam_slurm_adopt.

3. NVIDIA driver hardening

  • Driver repo: install from NVIDIA's Rocky 9 repo, then pin the version with dnf versionlock so unattended updates don't swap drivers in production.
  • Security bulletins: subscribe to NVIDIA's security bulletins and set a patch cadence. Driver CVEs come out several times a year, and your vulnerability scanner should flag them too.

  • Profiling restriction: make sure /etc/modprobe.d/nvidia.conf contains the line below. Recent drivers default to it, but setting it explicitly protects against a package or local change turning it off. It blocks the performance-counter side channel that lets one user profile another user's GPU work.

    options nvidia NVreg_RestrictProfilingToAdminUsers=1

  • Persistence daemon: enable nvidia-persistenced instead of setting persistence mode by hand, and run it as a non-root user.

  • SELinux: keep it enforcing. The NVIDIA driver works with it, so investigate AVC denials rather than switching it off.

4. Job prolog and epilog

  • Stray processes: in the epilog, check for leftover GPU processes with nvidia-smi --query-compute-apps=pid --format=csv,noheader and kill any you find. If they won't die, drain the node with a reason so the next user doesn't inherit a dirty GPU.
  • GPU settings: return application clocks and compute mode to your site baseline in case a job changed them (for example, nvidia-smi -rac, then re-apply your standard compute mode).
  • Health check: run a quick check before returning the node, either dcgmi diag -r 1 or NHC with GPU checks.
  • Sharing modes: use EXCLUSIVE_PROCESS compute mode as the baseline on shared nodes, and don't run MPS across different users.

5. MIG (A100/H100-class and newer GPUs)

  • Partitioning: use MIG rather than MPS or time-slicing for multi-user sharing. MIG gives hardware memory isolation; the other two don't.
  • Persistence: manage MIG layouts with nvidia-mig-parted so they survive reboots, and let AutoDetect=nvml expose the slices as GRES.

6. Containers

  • Apptainer: set allow setuid = no in apptainer.conf and use unprivileged user-namespace mode. Users run GPU containers with --nv.
  • NVIDIA Container Toolkit: if installed, keep it on the latest release. CVE-2024-0132 and CVE-2025-23266 were both container escapes.
  • Image sources: point users to an approved registry or a local cache of vetted NGC images instead of arbitrary Docker Hub pulls.

7. Monitoring and detection

  • Metrics: run dcgm-exporter on GPU nodes and scrape it from your existing Prometheus.
  • Idle-node alert: alert when GPU utilization is above about 10% on a node Slurm reports as idle. That's the classic cryptomining signal.
  • Xid errors: forward kernel logs centrally and alert on Xid codes. Treat 48, 63, 64, 79, 94, and 95 as high priority. Xid 79 means the GPU fell off the bus, and 48 is a double-bit ECC error.
  • DCGM hostengine: bind nv-hostengine (port 5555) to localhost or the management VLAN only.

8. Fabric (InfiniBand/RoCE)

  • Partitioning: configure P_Keys in OpenSM or UFM to separate tenant traffic from storage traffic.
  • Subnet Manager: run it on dedicated, locked-down hosts, and restrict who can run ibdiagnet or change SM configuration.
  • NVSwitch systems: keep nvidia-fabricmanager at the same version as the driver, with no external exposure.

9. Firmware and out-of-band management

  • Firmware inventory: track GPU VBIOS and NVSwitch firmware versions alongside BIOS, and update them with NVIDIA's firmware bundles during maintenance windows.
  • BMC network: keep iLO/iDRAC on an isolated management network with current firmware. A compromised BMC owns the GPUs too.

10. Data hygiene

  • Permissions: default dataset and scratch directories to 0750 or group-based access, never world-readable.
  • Model files: encourage safetensors over pickle-based checkpoints, since pickle files can execute code when loaded.
Examples are generic. Verify commands and defaults against your vendor and scheduler documentation before production use.
